# AGENTS.md

Курс по программированию от Всеволода Козлова (телеграм @Vsevolod026). 47 уроков от основ Python до полностековой веб-разработки. Сайт построен на MkDocs Material, исходники уроков — markdown-файлы в `docs/lessonN/lessonN.md`. Навигация настраивается в `mkdocs.yml`.

## Структура урока

Шаблон на примере уроков 45–47:

```
# Урок N. Название темы

Вводный абзац (1–3 строки) — чему научится ученик.

## Тема 1

Текстовое объяснение концепта.

```python
# пример кода с комментированным выводом
```

### Подтема

Уточнение внутри темы.

## Итоги

- Маркированный список ключевых выводов

## Домашнее задание

Практические задачи от простого к сложному.
```

### Использование заголовков

- `#` — заголовок урока, формат `Урок N. Название темы`
- `##` — крупные разделы (тема, «Итоги», «Домашнее задание»)
- `###` — подтемы внутри раздела
- `---` — горизонтальная линия для визуального разделения крупных смысловых блоков (между разделами с разной тематикой)

## Принципы написания урока

### Демонстрируйте на конкретных примерах кода

Каждый концепт сопровождается runnable код-блоком с комментированным выводом. Ученик должен видеть, что именно вернёт код. Не объясняйте теорию без примера.

```python
movie = MovieData(title="Титаник", views=100)
print(movie)
# title='Титаник' views=100
```

### Задавайте вопросы для самопроверки

В ходе урока вставляйте короткие упражнения или вопросы, чтобы ученик мог проверить понимание материала до перехода к следующей теме.

```markdown
**Упражнения:**
1. Объяви `let`-переменную `temperature` без начального значения. Выведи в консоль её значение. Подумай, есть ли аналог в Python.
2. Попробуй изменить `const`-переменную. Какую ошибку ты получишь?
```

### Домашнее задание

- Располагается в конце урока под заголовком `## Домашнее задание`
- Задачи идут от простого к сложному
- Описывайте **что** нужно сделать, а не **как** — не давайте подсказки о способе реализации
- Для каждой задачи приводите входные данные и ожидаемый результат
- Указывайте ориентировочное время выполнения
- При необходимости давайте ссылки на предыдущие уроки, материалы которых пригодятся

### Описание проектов

Когда домашнее задание — это полноценный проект (а не набор коротких задач), описывайте его как техническое задание. Структура:

1. **Цель проекта** — что создаётся, какие знания закрепляет.
2. **Описание программы** — что делает, как пользователь взаимодействует.
3. **Функциональные требования** — детальное описание каждой части (экрана, эндпоинта, компонента) в отдельных подтемах.
4. **Технические требования** — файловая структура, инструменты, API.
5. **Критерии проверки** — чек-лист для самопроверки.
6. **Возможности для расширения** — опциональные улучшения (по желанию).
7. **Ссылки** — на документацию и предыдущие уроки.

Примеры: урок 11 (описание идей проектов), урок 37 (ТЗ портфолио), урок 44 (CRUD-приложение).

## Технические детали

- Уроки лежат в `docs/lessonN/lessonN.md` (файл внутри директории урока)
- Новые уроки нужно добавлять в навигацию `mkdocs.yml` в секцию `nav`
- Проверка сборки: `.venv/bin/python -m mkdocs build --strict`
- Локальный сервер: `.venv/bin/python -m mkdocs serve`
- Линтеры: `ruff.toml` (Python), `prettierrc.json` (frontend)
- Python 3.13, управление зависимостями через `uv`
- Markdown-расширения: `admonition`, `pymdownx.superfences`, `pymdownx.highlight`, `pymdownx.inlinehilite`, `pymdownx.arithmatex` (KaTeX для формул)
