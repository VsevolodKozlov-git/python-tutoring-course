# Урок 43. API: Авторизация, фильтрация

## Авторизация в API

Чтобы API могло вас идентифицировать, используются **токены**.  
Когда вы вводите логин и пароль на сайте, сервер проверяет их и выдаёт токен. Браузер сохраняет его и при каждом следующем запросе отправляет вместе с запросом.

Если бы токенов не существовало, любой мог бы прочитать вашу переписку в соцсетях или перевести деньги с вашего банка

Токен передаётся в HTTP-заголовке `Authorization`. Сервер получает токен, проверяет его подлинность и понимает, что запрос делает именно ваш аккаунт.

### Добавление токена в Axios

Чтобы отправить токен через Axios, достаточно передать объект с заголовками:

```javascript
await axios.get(url, {
  headers: {
    Authorization: 'Bearer your_token_here',
  },
})
```

> Обратите внимание на формат: обычно перед токеном пишут слово `Bearer` с пробелом. Некоторые API требуют просто токен без префикса — смотрите документацию конкретного сервиса.

## Обращение к API через Postman

**Postman** — графический инструмент для выполнения HTTP-запросов прямо из браузера или десктопного приложения.  

С помощью Postman удобно:

- проверить, работает ли API;
- посмотреть формат и содержимое ответа;
- протестировать авторизацию;

Подробно использование Postman мы разберём на уроке.

## Структура API на примере LOTR API

**LOTR API** — сервис, предоставляющий информацию о вселенной «Властелина Колец».

Документация со всеми endpoint’ами доступна [здесь](https://the-one-api.dev/documentation).  

Каждый **endpoint** (конечная точка) возвращает определённый тип данных и связывается с другими endpoint’ами через **уникальные идентификаторы (id)**.

### Пример: получение случайной цитаты

Запрос к `/quote/random` может вернуть такой JSON:

```json
{
  "_id": "5cd96e05de30eff6ebcced8a",
  "dialog": "The shards of Narsil, The blade that cut the Ring from Sauron's hand...",
  "movie": "5cd95395de30eff6ebccde5c",
  "character": "5cd99d4bde30eff6ebccfc57",
  "id": "5cd96e05de30eff6ebcced8a"
}
```

Вместо названий фильмов и персонажей мы видим длинные последовательности символов — это **уникальные идентификаторы (id)**.  
Чтобы получить полную информацию о персонаже или фильме, нужно выполнить отдельный запрос к соответствующему endpoint’у с этим id.

- Информация о персонаже: `GET /character/5cd99d4bde30eff6ebccfc57`  
- Информация о фильме: `GET /movie/5cd95395de30eff6ebccde5c`

**Пример ответа `/character/{id}`:**

```json
{
  "docs": [
    {
      "_id": "5cd99d4bde30eff6ebccfc57",
      "name": "Boromir",
      "wikiUrl": "http://lotr.wikia.com//wiki/Boromir",
      "race": "Human",
      "birth": "TA 2978",
      "gender": "Male",
      "death": "February 26 ,3019",
      "hair": "Dark (book) Light brown (movie)",
      "height": null,
      "realm": null,
      "spouse": null
    }
  ],
  "total": 1,
  "limit": 1000,
  "offset": 0,
  "page": 1,
  "pages": 1
}
```

Таким образом, чтобы собрать полную информацию, часто нужно делать несколько связанных запросов.

## Фильтрация данных

Чтобы получать только нужные данные, разработчики API добавляют возможность **фильтрации**.  
Фильтры передаются как параметры GET-запроса.

Параметры записываются в URL после вопросительного знака `?`, в формате `ключ=значение`. Несколько параметров разделяются символом `&`. Вы с ними уже встречались не раз, например, когда искали товары на озоне

**Пример:** получить всех персонажей расы Хоббит:  
`GET /character?race=Hobbit`

Конкретный набор доступных фильтров описан в документации API.

В Axios параметры можно передавать двумя способами:

1. Прямо в URL:
   ```javascript
   await axios.get('https://the-one-api.dev/v2/character?race=Hobbit')
   ```

2. Через свойство `params` (удобнее, особенно если параметров много):
   ```javascript
   await axios.get('https://the-one-api.dev/v2/character', {
     params: { race: 'Hobbit' }
   })
   ```

Оба варианта эквивалентны.
