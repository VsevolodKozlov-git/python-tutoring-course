    Итого 8.9

    Steam API: два API и их отличия

    В проекте используются два разных API Steam. Они находятся на разных доменах, по-разному работают с авторизацией и возвращают разные данные.

    Steam Web API

    Домен: api.steampowered.com

    Основной API для получения статистики, новостей и достижений. Требует API-ключ — он передаётся как query-параметр key в каждом запросе.

    Получить ключ можно бесплатно на странице https://steamcommunity.com/dev/apikey (потребуется войти в аккаунт Steam).

    Документация: https://partner.steamgames.com/doc/webapi

    Пример запроса:

    https://api.steampowered.com/ISteamUserStats/GetNumberOfCurrentPlayers/v1/?appid=730&key=ВАШ_КЛЮЧ

    Steam Store API

    Домен: store.steampowered.com/api

    Неофициальный API для получения информации о играх: название, описание, жанры, цена, обложка. Не требует API-ключа.

    Официальной документации нет, но API широко используется сообществом.

    Пример запроса:

    https://store.steampowered.com/api/appdetails?appids=730&l=russian

    Авторизация через .env

    API-ключ для Steam Web API — это секретные данные. Хранить ключ прямо в коде нельзя. Ключ загружается из файла .env через библиотеку python-dotenv.

    Как работать с .env описано в уроке 48_study.

    1. Цель проекта

    Создать веб-приложение, которое по appID игры показывает сводную страницу: описание, текущий онлайн, новости и достижения. Проект закрепляет знания FastAPI (эндпоинты, query-параметры, Pydantic-модели), Vue.js (формы, таблицы, работа с API) и обработки данных от внешних API на бэкенде.

    2. Описание программы

    Пользователь вводит appID игры в форму на фронтенде, при желании указывает фильтры (количество новостей, минимальный процент достижений). При отправке формы фронтенд делает несколько запросов к разным эндпоинтам бэкенда FastAPI. Бэкенд обращается к Steam API напрямую, получает данные, нормализует их через Pydantic-модели, фильтрует и возвращает JSON. Фронтенд отображает результат: карточку игры (название, описание, жанры, цена, обложка), текущий онлайн, таблицу новостей и таблицу достижений.

    3. Функциональные требования

    3.1. Форма поиска и фильтрации

    Форма на фронтенде содержит:

    • appID — текстовое поле, обязательное (например, 730 для CS2, 440 для TF2, 570 для Dota 2)
    • Количество новостей — выпадающий список (5 / 10 / 20), по умолчанию 5
    • Минимальный процент достижений — числовое поле (0–100), по умолчанию 0 (показывать все)
    • Кнопка «Найти»

    При нажатии «Найти» фронтенд отправляет запросы ко всем эндпоинтам бэкенда, передавая appID и соответствующие параметры фильтрации.

    3.2. Карточка игры

    Данные получены с эндпоинта GET /game-info?appid={appid} (бэкенд обращается к https://store.steampowered.com/api/appdetails?appids={appid}&l=russian).

    Отображается:

    • Обложка (header_image)
    • Название (name)
    • Краткое описание (short_description)
    • Жанры (список бейджей)
    • Цена: если is_free — бейдж «Бесплатно», иначе — final_formatted из price_overview. Если со скидкой — показать старую и новую цену + процент скидки.

    3.3. Текущий онлайн

    Данные получены с эндпоинта GET /players?appid={appid} (бэкенд обращается к https://api.steampowered.com/ISteamUserStats/GetNumberOfCurrentPlayers/v1/?appid={appid}&key=ВАШ_КЛЮЧ).

    Отображается число игроков онлайн прямо сейчас (player_count). Число должно быть отформатировано (например, 839 875).

    3.4. Таблица новостей

    Данные получены с эндпоинта GET /news?appid={appid}&count={count} (бэкенд обращается к https://api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid={appid}&count={count}&key=ВАШ_КЛЮЧ).

    Таблица с новостями, колонки:

    • Дата — отформатированная из unix-timestamp (например, 06.09.2026)
    • Заголовок (title) — кликабельная ссылка на url
    • Автор (author)
    • Теги — бейджи из массива tags

    Количество новостей ограничено параметром из формы.

    3.5. Таблица достижений

    Данные получены с эндпоинта GET /achievements?appid={appid}&min_percent={percent} (бэкенд обращается к https://api.steampowered.com/ISteamUserStats/GetGlobalAchievementPercentagesForApp/v2/?gameid={appid}&key=ВАШ_КЛЮЧ).

    Таблица с достижениями, колонки:

    • Название (name)
    • Процент выполнения (percent) — с бейджем цвета: зелёный если > 50%, жёлтый если 20–50%, красный если < 20%

    Достижения отфильтрованы по минимальному проценту из формы. Отсортированы по убыванию процента.

    Примечание: не у всех игр есть достижения (CS2 — 1 шт., у некоторых — 0). Если достижений нет, показывается сообщение «Нет данных о достижениях».

    3.6. Обработка ошибок

    • Если appID не существует (Store API вернул success: false) — показать сообщение «Игра не найдена»
    • Если бэкенд вернул ошибку — показать всплывающее уведомление (toast)

    4. Технические требования

    4.1. Бэкенд (FastAPI)

    Структура файлов:

    backend/
  api.py          — эндпоинты FastAPI
  models.py       — Pydantic-модели
  config.py       — загрузка API-ключа из .env
  main.py         — точка входа (uvicorn.run)
.env              — файл с переменными окружения (STEAM_API_KEY=...)

    Эндпоинты:

    Эндпоинт URL Steam API query-параметры эндпоинта
    GET /game-info https://store.steampowered.com/api/appdetails?appids={appid}&l=russian appid
    GET /players https://api.steampowered.com/ISteamUserStats/GetNumberOfCurrentPlayers/v1/?appid={appid}&key=ВАШ_КЛЮЧ appid
    GET /news https://api.steampowered.com/ISteamNews/GetNewsForApp/v2/?appid={appid}&count={count}&key=ВАШ_КЛЮЧ appid, count
    GET /achievements https://api.steampowered.com/ISteamUserStats/GetGlobalAchievementPercentagesForApp/v2/?gameid={appid}&key=ВАШ_КЛЮЧ appid, min_percent

    Логика бэкенда (обработка данных, не проксирование):

    Бэкенд обращается к Steam API напрямую при помощи httpx или requests. API-ключ для Steam Web API загружается из .env. Для Store API ключ не нужен.

    Каждый эндпоинт получает сырой ответ от Steam API, извлекает нужные поля, нормализует их (преобразует типы, форматирует даты, отбрасывает лишнее) и возвращает через Pydantic-модель. Данные, полученные из внешнего API, обязательно проходят валидацию через Pydantic-модели — это гарантирует, что ответ бэкенда всегда имеет корректную структуру и типы. Данные, которые возвращаются на фронтенд, должны быть очищены от лишних полей и приведены к удобному виду.

    • /game-info — если Store API вернул success: false, выбросить HTTPException(404).
    • /news — преобразовать unix-timestamp в дату, оставить только нужные поля (отбросить contents, feedlabel, feed_type).
    • /achievements — отфильтровать по min_percent, отсортировать по убыванию, преобразовать percent из строки в число.

    4.2. Фронтенд (Vue.js + Nuxt UI)

    • Экземпляр Axios с baseURL на бэкенд
    • Форма (UForm) с полями: UInput для appID, USelect для количества новостей, UInput для минимального процента, UButton «Найти»
    • Карточка игры с обложкой, описанием, бейджами жанров, ценой
    • Число онлайна
    • UTable для новостей
    • UTable для достижений с кастомными ячейками (UBadge для процентов и тегов)
    • useToast для ошибок

    5. Требования к коду

    1. Данные, полученные из Steam API, проходят валидацию через Pydantic-модели — ответ бэкенда всегда имеет корректную структуру и типы.
    2. Бэкенд преобразует сырые ответы Steam API в данные удобные для frontend: unix-timestamp → дата, percent → число, лишние поля отбрасываются, достижения фильтруются и сортируются.
    3. При несуществующем appID — сообщение «Игра не найдена».
    4. API-ключ загружается из .env, и не захардкожен в исходном коде.

    6. Возможности для расширения

    • Сравнение двух игр бок о бок (два appID в форме)
    • Сохранение истории поиска (список недавно просмотренных игр)
    • График онлайна по времени (регулярные запросы и сохранение в список)
    • Поиск игры по названию через ISteamApps/GetAppList/v2
