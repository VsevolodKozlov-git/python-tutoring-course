    Урок 52. Задание 26 из ЕГЭ. Жадные алгоритмы 💰

    В этом уроке разбираем жадный подход — технику, в которой на каждом шаге делаем лучший выбор. Начнём с простых задач (сокровищница, размен монет), а затем решим два задания 26 ЕГЭ: «Санта-Клаус и подарки» и «Туристический маршрут».

    Что такое жадный алгоритм

    Жадный алгоритм — это подход, в котором на каждом шаге мы выбираем вариант, который выглядит лучшим прямо сейчас, не рассматривая все возможные пути целиком. Если задача устроена так, что «лучшее сейчас» не вредит будущему, то цепочка локально лучших выборов приводит к глобально оптимальному ответу.

    Ваша задача — корректно построить жадный обход: в каком порядке обходить элементы и при каком условии брать текущий.

    Базовый шаблон жадного решения:

    1. Отсортировать данные в нужном порядке (по убыванию, по времени окончания, …).
    2. Сделали один обход, на каждом шаге решая: брать текущий элемент или пропустить.

    Базовая задача: Сокровищница

    Представьте, что в сокровищнице лежат предметы разной стоимости — список prices. Забрать можно только n сокровищ. Какое наибольшее количество денег мы можем заработать?

    Жадный ход очевиден: на каждом шаге забираем самое дорогое из оставшихся. Это то же самое, что отсортировать prices по убыванию и взять первые n.

    Решение 
    prices = [5, 8, 3, 10, 7]
n = 3

prices.sort(reverse=True)
print(sum(prices[:n]))
# 25

    Вопрос: какой будет ответ, если prices = [100, 50, 50, 49, 1], n = 2?

    Ответ 150 — после сортировки по убыванию первые два элемента: 100 и 50.

    Задание 26 ЕГЭ. Санта-Клаус и подарки

    Условие задания

    Идея решения:

    1. Сортируем весы по убыванию: nums.sort(reverse=True) — жадный обход идёт от самых крупных.
    2. Делаем один проход и на каждом шаге берём элемент, только если выполнены условия из условия задачи относительно последнего взятого:
    3. mod_current != mod_last — чётность веса чередуется (чётный, нечётный, чётный, …);
    4. box_size_last - box_size_current >= 7 — разность весов с последним взятым не меньше 7. Мы идём по убыванию, поэтому последний взятый всегда не меньше текущего — и разность не отрицательна.
    5. Чётность первого взятого элемента может быть любой — поэтому прогон делаем дважды: старт от чётного (get_boxes(0)) и от нечётного (get_boxes(1)), а из двух результатов берём лучший.
    Решение 
    with open('26.txt', 'r') as file:
    file.readline()
    nums = list(map(int, file.readlines()))

nums.sort(reverse=True)

def get_boxes(mod):
    box_size_last = float('inf')
    mod_last = mod
    boxes = 0

    for box_size_current in nums:
        mod_current = box_size_current % 2 
        if mod_current != mod_last and (box_size_last - box_size_current) >= 7:
            boxes += 1
            box_size_last = box_size_current
            mod_last = mod_current
    return boxes, box_size_last

print(get_boxes(0))
print(get_boxes(1))

    Два момента по коду:

    • Первая строка файла — количество элементов, её пропускаем file.readline(), остальные строки читаем как числа.
    • box_size_last = float('inf') — «последний взятый» вес бесконечным, чтобы первый подходящий элемент всегда прошёл проверку на разность ≥ 7.

    Вопрос: зачем нужны два прохода — get_boxes(0) и get_boxes(1)?

    Ответ Первый взятый элемент может быть как чётным, так и нечётным — заранее не знаем, какой старт даст длиннее цепочку. Поэтому пробуем оба и берём лучший результат.

    Задание 26 ЕГЭ. Туристический маршрут

    Условие задания

    Каждая строка файла — маршрут: время начала и длительность.

    Идея решения:

    Главный жадный принцип: маршрут, который заканчивается раньше, всегда лучше — он оставляет больше места для последующих маршрутов. Поэтому:

    1. Считаем конец каждого маршрута: end = start + length. Код переписывает пару как (end, length).
    2. Сортируем маршруты по времени окончания по возрастанию — «всегда брать самые короткие и самые ранние».
    3. Идём по маршрутам по порядку. Список best хранит пары (количество маршрутов, время конца последнего) — оптимальный вариант в каждой «опорной точке». Для нового маршрута два варианта:
    4. не брать его — оптимум остаётся прежним: cnt_best, end_best = best[-1];
    5. взять — ищем в best в обратном порядке первую пару, у которой конец не позже начала текущего маршрута (end_prev <= end_cur - length_cur), и прибавляем к её количеству 1.
    6. Ответ — последний элемент best: максимальное количество маршрутов.

    Почему ищем в обратном порядке и сразу останавливаемся: количества в best не убывают (каждый новый элемент наследует количество предыдущего и может только его улучшить). Значит, среди подходящих маршрутов лучший — самый поздний, и первая найденная в reversed(best) пара уже даёт максимум.

    Решение 
    def transform(s):
    vals = s.split()
    return tuple(map(int, vals))

with open('26_2.txt', 'r') as file:
    file.readline()
    inp = list(map(transform, file.readlines()))

inp = list(map(lambda x: (x[0] + x[1], x[1]), inp))
inp.sort(key=lambda x: x[0])

best = []

for end_cur, length_cur in inp:
    if len(best):
        cnt_best, end_best = best[-1]
    else:
        cnt_best, end_best = 1, end_cur
    for cnt_prev, end_prev in reversed(best):
        if end_prev <= end_cur - length_cur:
            if cnt_prev + 1 >= cnt_best:
                cnt_best = cnt_prev + 1
                end_best = end_cur
            break
    best.append((cnt_best, end_best))

print(best[-1])

    Вопрос: почему маршруты сортируются по времени окончания, а не по началу?

    Ответ Наши ограничения — про интервалы между маршрутами: следующий можно начать, только когда предыдущий закончился (плюс время на остановку). Раннее окончание освобождает время для остальных маршрутов, а раннее начало само по себе ничего не гарантирует — длинный маршрут может начать рано, но закончить поздно.

    Итоги

    • Жадный алгоритм — лучший выбор на каждом шаге. Работает, когда «лучшее сейчас» не вредит будущему
    • Базовый шаблон: отсортировать данные в нужном порядке и сделать один обход с условием на взятие текущего элемента.
    • Если старт жадного обхода заранее не известен — пробуем все варианты старта и берём лучший (в задаче Санта-Клауса — два прохода).

    1. Разделение строки на сбалансированные строки

    LeetCode 1221

    Сбалансированная строка — это строка, в которой одинаковое количество символов 'L' и 'R'.

    Дана сбалансированная строка s. Разбейте её на несколько подстрок так, чтобы:

    • каждая подстрока была сбалансированной.

    Верните максимальное количество сбалансированных строк, которое можно получить.

    Пример 1: Вход: s = "RLRRLLRLRL" Выход: 4 Пояснение: s можно разбить на "RL", "RRLL", "RL", "RL" — в каждой подстроке одинаковое количество 'L' и 'R'.

    Пример 2: Вход: s = "RLRRRLLRLL" Выход: 2 Пояснение: s можно разбить на "RL", "RRRLLRLL". Обратите внимание: разбить на "RL", "RR", "RL", "LR", "LL" нельзя, так как 2-я и 5-я подстроки не сбалансированы.

    Пример 3: Вход: s = "LLLLRRRR" Выход: 1 Пояснение: s можно разбить только как "LLLLRRRR".

    Ограничения: - 2 <= s.length <= 1000 - s[i] — либо 'L', либо 'R' - s — сбалансированная строка

    2. Минимальное количество операций для увеличения массива

    LeetCode 1827

    Дан массив целых чисел nums (нулевая индексация). За одну операцию можно выбрать элемент массива и увеличить его на 1.

    • Например, если nums = [1,2,3], можно увеличить nums[1], получится nums = [1,3,3].

    Верните минимальное количество операций, необходимое, чтобы сделать nums строго возрастающим.

    Массив nums строго возрастает, если nums[i] < nums[i+1] для всех 0 <= i < nums.length - 1. Массив длины 1 тривиально строго возрастает.

    Пример 1: Вход: nums = [1,1,1] Выход: 3 Пояснение: можно выполнить следующие операции: 1) увеличить nums[2] → nums становится [1,1,2]; 2) увеличить nums[1] → nums становится [1,2,2]; 3) увеличить nums[2] → nums становится [1,2,3].

    Пример 2: Вход: nums = [1,5,2,4,1] Выход: 14

    Пример 3: Вход: nums = [8] Выход: 0

    Ограничения: - 1 <= nums.length <= 5000 - 1 <= nums[i] <= 10^4
