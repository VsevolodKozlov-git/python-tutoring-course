    Урок 53. Задание 26 ЕГЭ: сортировка и проверка кода

    Сегодня мы будем не только решать задачи, но и думать, как проверять наши решения. Потратить 5 минут на проверку важно, так как без неё мы с большой вероятностью можем ошибиться.

    Как проверять решение

    Для проверки хватит расставлять print внутри кода. Но что же нам надо проверять?

    Условно тесты можно поделить на 2 вида:

    Blackbox

    Blackbox — когда мы не тестируем внутреннее устройство кода, а смотрим только на ожидаемый вход и выход. Для blackbox нам нужны только входное и выходное значения.

    Примером blackbox-теста является само задание ЕГЭ: составители знают входные данные и ожидаемый результат.

    Например, нам надо найти наибольшее число из входных данных:

    1
2001
10001
17001
16001
5

    Ожидаемый результат: 17001. И составителям неважно, как вы его получили. Главное, что вы его получили.

    Итог: для blackbox не надо знать механику работы алгоритма — достаточно знать ожидаемые входные и выходные данные.

    Whitebox

    Whitebox — тестирование, когда важна внутренняя работа алгоритма.

    Пусть для решения задачи выше вы написали такой код:

    largest = None
with open('whitebox.txt') as f:
    while (line := f.readline()):
        if largest is None:
            largest = line
        else:
            largest = max(line, largest)

print(largest)

    Вы сделали blackbox-проверку и получили 5. Такой результат вас смутил, ведь вы ожидали 17001. Вы решаете понять, почему так происходит, поэтому делаете whitebox-проверку: при помощи print выводите самое большое число на момент каждой итерации. Допустим, у вас получилось:

    1

2001

2001

2001

2001

5

    Странные дела. Первая итерация правильная. Вторая тоже, но потом 10001 не заменило 2001. Значит, проблема началась с этого сравнения. Также почему-то выводятся пустые строки, хотя print всего один.

    Вопрос: почему blackbox-тест выдал 5, а не 17001?

    Ответ В коде нет преобразования в `int`, поэтому `max` сравнивает строки, а не числа. В лексикографическом порядке `"5"` больше `"2001"`, потому что первый символ `'5'` больше `'2'`. По этой же причине в выводе пустые строки: в переменных хранятся строки вместе с символом переноса строки `\n`, а `print` добавляет ещё один.

    Граничные значения

    Когда мы разобрались с двумя видами тестирования, поговорим более конкретно о blackbox. Входных данных даже для такой задачи, как сравнение чисел, может быть бесконечное количество, как и выходных.

    Поэтому в тестировании не проверяют всё подряд, а сосредотачиваются на граничных значениях. На них зачастую происходят ошибки, поэтому разумнее всего проверить именно их.

    Пусть у нас дано задание: на вход дают список возрастов, возможно пустой. Выведите количество людей, которые достигли совершеннолетия.

    Вопрос: где здесь граничные точки?

    Ответ - Вход: пришёл пустой список. Ожидание: `0`. - Возраст: `17`. Ожидание: не включаем. - Возраст: `18`. Ожидание: включаем. Логика такая: зачем проверять все возраста от 0 до 100, когда можно просто проверить граничные значения? Если мы проверим 17 и 18, вероятность, что алгоритм ошибётся в другом месте, остаётся, но падает на 95%.

    Задачи ЕГЭ

    В задании ниже дан код с ошибкой. Сначала попробуйте найти её сами, потом сверьтесь с разбором и правильным решением.

    Задача 1

    Условие задания

    Что делает код: по записям «номер читателя — номер книги» для каждой книги ищет самый длинный отрезок подряд идущих номеров читателей и по правилам из условия выводит длину отрезка и номер книги.

    Решение с ошибкой 
    from collections import defaultdict

book_reader_dict = defaultdict(set)
with open('26_3.txt', 'r') as f:
    n = int(f.readline())

    for _ in range(n):
        line = f.readline()
        reader, book = line.split()
        reader = int(reader)
        book = int(book)
        book_reader_dict[book].add(reader)

book_best = None
length_best = 0

for book in book_reader_dict:
    readers = book_reader_dict[book]
    readers = sorted(list(readers))
    length = 1
    for i in range(1, len(readers)):
        if readers[i] == readers[i - 1] - 1:
            length += 1
        else:
            length = 1
        if length > length_best:
            book_best = book
            length_best = length

print(book_best)
print(length_best)

    Вопрос: найдите ошибку в коде.

    Разбор ошибки 1. `readers[i] == readers[i - 1] - 1` — неверный знак. Список `readers` отсортирован по возрастанию, поэтому следующий подряд идущий читатель отличается на **плюс 1**, а не на минус 1. С `-1` условие никогда не выполняется, и длина отрезка для любой книги остаётся `1`. 2. `for book in book_reader_dict` — книги обходятся в порядке их появления во входном файле, а не по возрастанию номера. 3. `length > length_best` — строгое сравнение. В паре с пунктом 2 это ломает правило при равенстве: корректный код обходит книги по возрастанию (`sorted`) и обновляет результат при `>=`, поэтому при нескольких книгах с одинаковой максимальной длиной отрезка выбирается книга с наибольшим номером. 4. Порядок вывода: сначала книга, потом длина. А нужно наоборот — сначала длина, потом номер книги.
    Правильное решение 
    from collections import defaultdict

book_reader_dict = defaultdict(set)
with open('26_3.txt', 'r') as f:
    n = int(f.readline())

    for _ in range(n):
        line = f.readline()
        reader, book = line.split()
        reader = int(reader)
        book = int(book)
        book_reader_dict[book].add(reader)

book_best = None
length_best = 0

for book in sorted(book_reader_dict.keys()):
    readers = book_reader_dict[book]
    readers = sorted(list(readers))
    length = 1
    for i in range(1, len(readers)):
        if readers[i] == readers[i - 1] + 1:
            length += 1
        else:
            length = 1
        if length >= length_best:
            book_best = book
            length_best = length

print(length_best)
print(book_best)

    Итоги

    • Проверка — часть решения: без 5 минут на проверку с большой вероятностью останемся с ошибкой.
    • Blackbox — проверяем только вход и ожидаемый выход, механика алгоритма не важна. Само задание ЕГЭ — blackbox-тест.
    • Whitebox — проверяем внутреннюю работу: при неожиданном результате выводим промежуточные состояния на каждой итерации и ищем, с какого шага пошло не так.
    • Классическая причина «почти работающего» кода: сравнение строк вместо чисел (нет int()).
    • Тестируем не все входы, а граничные значения: пустой вход, пороги (17/18).
    • Типичные ошибки в кодах ЕГЭ: знак в сравнении (+1/-1), порядок обхода элементов, строгое и нестрогое сравнение при равенстве, порядок вывода ответа.

    Решите задачу так, как вы бы это делали на экзамене: сначала напишите решение, а прежде чем отправить ответ — проверьте его:
